Architektura firmware

Warstwy

Firmware jest podzielony na kilka warstw aplikacyjnych:

  • warstwa startowa i wspolne zasoby: app.c, app.h,
  • warstwa radiowa aplikacji: radio_main.c, radio_main.h,
  • biblioteka radiowa i backendy modulacji: radio_lib/,
  • ramka i kryptografia LAVIET: laviet_frame.*, laviet_crypto.*,
  • security i storage: security_main.*, i2c_mem_store_lib/, st33ktpm2x_lib/,
  • lokalny UI: menu_main.*, lcd_main.*, button_main.*, lcd_library/,
  • sensory i sygnalizacja: bmp280_*, tof_*, led_array_*,
  • konsola serwisowa: service.*.

Zadania RTOS

Glowne moduly aplikacji dzialaja jako zadania CMSIS-RTOS2/FreeRTOS:

  • radio_main_create_task() tworzy zadanie radia i kolejke komend,
  • security_main_create_task() tworzy zadanie security i kolejke komend,
  • menu_main_create_task() obsluguje ekran menu oraz notyfikacje,
  • lcd_main_create_task() zarzadza fizycznym odswiezaniem LCD,
  • button_main_create_task() wykonuje polling/debounce przyciskow,
  • service_uart_create_task() tworzy opcjonalna konsole UART,
  • bmp280_main_create_task(), tof_main_create_task() i led_array_main_create_task() uruchamiaja zadania peryferyjne.

Wspolna magistrala I2C

Dostep do I2C jest serializowany przez helpery z app.h. Moduly korzystaja z app_i2c_master_transmit(), app_i2c_master_receive(), app_i2c_mem_write() i app_i2c_mem_read(), zeby unikac kolizji na wspolnej magistrali oraz miec jedno miejsce odzyskiwania po bledach magistrali.

Runtime configuration

radio_main_runtime_cfg_t opisuje pelny snapshot profili radiowych i flag runtime. security_runtime_cfg_t rozszerza go o ustawienia security i dane utrwalane w magazynie.
