\hypertarget{md_README_autotoc_md1}{}\doxysection{\texorpdfstring{1. Opis systemu}{1. Opis systemu}}\label{md_README_autotoc_md1}
BEKO to bezprzewodowy system pagerowy pracujący w topologii {\bfseries{gwiazdy}}. ~\newline
 W systemie występuje\+:


\begin{DoxyItemize}
\item jeden węzeł centralny\+: {\bfseries{Raspberry Pi Gateway}},
\item adresy node’ów STM32 w zakresie {\ttfamily 0x0002..0x\+FFFE},
\item komunikacja radiowa przez obecny backend {\bfseries{SX1276/\+RFM95}}.
\end{DoxyItemize}

Firmware noda przechowuje obecnie do {\bfseries{15 zaufanych urządzeń}} w lokalnych slotach trusted storage. Nie jest to limit adresacji radiowej.

Gateway wysyła wiadomości do wybranego node’a albo do całej sieci. ~\newline
 Każda poprawnie odebrana wiadomość z gatewaya musi zostać potwierdzona przez node ramką {\ttfamily ACK}.

Adresacja w ramce {\ttfamily LAVIET\+\_\+\+FRAME\+\_\+\+V1} jest 16-\/bitowa\+:


\begin{DoxyItemize}
\item {\ttfamily 0x0000} – wartość nieważna,
\item {\ttfamily 0x0001} – Raspberry Pi Gateway,
\item {\ttfamily 0x0002..0x\+FFFE} – adresy node’ów,
\item {\ttfamily 0x\+FFFF} – broadcast.
\end{DoxyItemize}

W systemie może działać\+:


\begin{DoxyItemize}
\item {\bfseries{1 gateway}},
\item wiele urządzeń końcowych w zakresie adresów {\ttfamily 0x0002..0x\+FFFE},
\item aktualnie do {\bfseries{15 sparowanych wpisów trusted}} na jednym nodzie.
\end{DoxyItemize}

\hypertarget{md_README_autotoc_md25}{}\doxysection{\texorpdfstring{8. TPM i klucze}{8. TPM i klucze}}\label{md_README_autotoc_md25}
TPM jest głównym punktem zaufania w systemie.

Wszystkie operacje bezpieczeństwa, które mogą być wykonane w TPM i które są wspierane w przyjętej architekturze, powinny być wykonywane właśnie tam.

TPM jest używany do\+:


\begin{DoxyItemize}
\item przechowywania sekretu głównego urządzenia,
\item ochrony kluczy,
\item generowania danych losowych,
\item ochrony sekretów EEPROM,
\item wsparcia lokalnej rotacji root seeda.
\end{DoxyItemize}

Aktualny lifecycle sekretu\+:


\begin{DoxyEnumerate}
\item Przy starcie firmware inicjalizuje TPM przed storage.
\item Root seed jest odczytywany z TPM NV.
\item Główny, PP-\/protected index to {\ttfamily 0x01\+C10101}.
\item Starszy index {\ttfamily 0x01\+C10100} jest odczytywany tylko jako ścieżka migracyjna.
\item Jeśli seed musi zostać utworzony albo nadpisany, zapis do TPM NV wymaga aktywnego pinu {\bfseries{TPM PP}}.
\item Pin PP jest podłączony do samego TPM, pin {\ttfamily 7}, aktywny stanem {\ttfamily VDD}; nie jest odczytywany jako GPIO STM32.
\item Klucz szyfrowania sekretów EEPROM jest wyprowadzany z TPM-\/backed root seeda.
\end{DoxyEnumerate}

Index {\ttfamily 0x01\+C10101} jest definiowany z {\ttfamily PPWRITE}, {\ttfamily OWNERREAD} i {\ttfamily NO\+\_\+\+DA}. W praktyce rotacja klucza z menu {\ttfamily Security -\/\texorpdfstring{$>$}{>} Keys} wymaga trzymania przycisku TPM PP; bez tego UI pokaże {\ttfamily Hold TPM PP button}.

Klucze nie mogą być przechowywane w firmware w postaci jawnej. ~\newline
 Są wyprowadzane lub ładowane bezpiecznie przy starcie, a następnie używane tylko tymczasowo.

Parowanie odbywa się wyłącznie z gatewayem. Próg RSSI {\ttfamily -\/20 d\+Bm} jest traktowany jako ostrzeżenie diagnostyczne do walidacji praktycznej, a nie jako twarda blokada w pierwszym wdrożeniu.

Przebieg\+:


\begin{DoxyEnumerate}
\item Gateway wysyła {\ttfamily PAIR\+\_\+\+REQ}.
\item Node przechodzi w tryb parowania.
\item Użytkownik lokalnie potwierdza operację.
\item TPM wspiera ustanowienie materiału kryptograficznego.
\item Zapisywana jest relacja zaufania.
\item Wyprowadzane są klucze robocze.

System powinien wspierać rotację kluczy z użyciem {\bfseries{Diffie–\+Hellman}}.

Rotacja może być uruchamiana\+:


\begin{DoxyItemize}
\item okresowo,
\item po określonej liczbie wiadomości,
\item na żądanie administratora,
\item po incydencie bezpieczeństwa.
\end{DoxyItemize}

Lokalna rotacja root seeda na nodzie jest już zabezpieczona TPM PP. Radiowy protokół {\ttfamily KEY\+\_\+\+ROTATE} i docelowa wymiana DH/\+ECDH nadal wymagają dokończenia jako osobny przepływ.
