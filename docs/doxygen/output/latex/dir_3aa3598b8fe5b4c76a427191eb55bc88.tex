\item {\ttfamily LAVIET\+\_\+\+FRAME\+\_\+\+V1} używa {\ttfamily src\+\_\+id}, {\ttfamily dst\+\_\+id}, {\ttfamily msg\+\_\+id}, {\ttfamily counter}, {\ttfamily payload\+\_\+len} i {\ttfamily mac\+\_\+tag}.
\item Ramki są uwierzytelniane HMAC-\/\+SHA256, a payload może być szyfrowany AES-\/\+CTR.
\item Relay mesh/\+TTL został usunięty z bieżącej architektury; node działa w topologii gwiazdy z gatewayem.
\item Ochrona przed replay w pierwszym wdrożeniu używa monotonicznego {\ttfamily counter} dla relacji gateway-\/node i zapisuje go w małym slocie {\ttfamily secret} NVM.
\item {\ttfamily TPM PP} w obecnym hardware jest podłączony do samego modułu TPM, nie do GPIO MCU. Pin TPM PP to pin {\ttfamily 7}, aktywny stanem {\ttfamily VDD}.
\item TPM jest podłączony przez {\ttfamily I2\+C3} ({\ttfamily PC0} = SCL, {\ttfamily PC1} = SDA); reset {\ttfamily TPM\+\_\+\+RESET\#} jest na {\ttfamily PB0}, a {\ttfamily TPM\+\_\+\+DAVINT\#} / {\ttfamily PIRQ} na {\ttfamily PH0} jako {\ttfamily EXTI0}, aktywny niskim stanem.
\item Firmware używa TPM jako źródła trwałego root seeda\+:
\begin{DoxyItemize}
\item główny NV index\+: {\ttfamily 0x01\+C10101},
\item legacy read-\/only/migration index\+: {\ttfamily 0x01\+C10100},
\item atrybuty głównego indexu\+: {\ttfamily PPWRITE}, {\ttfamily OWNERREAD}, {\ttfamily NO\+\_\+\+DA}.
\end{DoxyItemize}
\item Zapis lub rotacja root seeda wymaga aktywnego TPM PP. STM32 nie odczytuje tego pinu jako GPIO; wymuszenie odbywa się przez TPM authorization ({\ttfamily TPM\+\_\+\+RH\+\_\+\+PLATFORM} dla {\ttfamily NV\+\_\+\+Write}).
\item Klucz szyfrowania sekretów EEPROM jest wyprowadzany z TPM-\/backed root seeda. Przy pierwszym starcie po zmianie firmware próbuje przepisać stare wpisy EEPROM z dawnego stałego klucza na klucz wyprowadzony z TPM.
\item PP nie zabezpiecza jeszcze całego pairingu radiowego. Jeśli pairing albo inne operacje administracyjne mają wymagać fizycznej obecności, trzeba dodać osobne TPM policy/session albo równoważny flow oparty o TPM.
